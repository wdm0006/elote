# elote — codebase map

Folder-level map (depth ≤ 2). ~11.5k LOC in `elote/`; 40 test files; 170 tracked files total.

| Path | What it holds |
|---|---|
| `elote/` | The installed package (typed: `py.typed`). |
| `elote/competitors/` | The rating models. `base.py` defines the shared `BaseCompetitor` ABC (`expected_score`, `beat`/`lost_to`/`tied`, `export_state`/`from_state`, `to_json`/`from_json`). One module per system: `elo`, `glicko`, `glicko2`, `glicko_boost`, `trueskill`, `ecf`, `dwz`, `colley`, `massey`, `keener`, `pythagorean`, `bradley_terry`, `whr`, `ensemble` (Blended). |
| `elote/arenas/` | Population management. `base.py` (`BaseArena` — matchups, leaderboard, history, `export_state`) and `lambda_arena.py` (`LambdaArena`, used across examples: creates competitors as identifiers appear, records bouts, returns best-first leaderboards, accepts `initial_state`). |
| `elote/datasets/` | Data adapters: `synthetic.py` (always available), `chess.py` (Lichess; needs `python-chess`, `pyzstd`), `football.py` (college football; needs `sportsdataverse`), plus `base.py`, `utils.py`. Gated behind the `datasets` extra. |
| `elote/*.py` | Top-level modules: `benchmark.py` (`DataSplit`, `evaluate_competitor`, `benchmark_competitors`), `evaluation.py` (metrics over `History`), `visualization.py` (plotting helpers), `logging.py`. |
| `tests/` | 40 pytest files: per-competitor behavioral + known-value tests, arenas, unified interface, serialization, datasets, benchmarks, calibration, visualization, examples (`test_examples.py` runs the example scripts). |
| `examples/` | Runnable scripts per rating system (`*_example.py`, `*_arena.py`) plus `use_cases/`. Run via `make run-example EXAMPLE=<file>`. |
| `scripts/` | `rating_system_comparison.py` (backs `make compare-systems`), `run_benchmarks.py`. |
| `docs/` | Sphinx docs: `source/` (incl. `rating_systems/` methodology pages), `Makefile`, `requirements.txt`. Build with `make docs`. |
| `images/` | Generated rating plots referenced by README and docs (regenerated by the test suite). |
| `.github/workflows/` | `test-suite.yml` (tox py310–py312 + ruff lint; PRs and pushes to master), `docs.yml` (publish docs on master push), `test-docs-build.yml` (docs validation on PRs), `pypi-publish.yml` (on release). |
| `.cursor/rules/` | Project conventions: Makefile-driven testing, how to implement new competitors, pytest / python / sphinx standards. |
| root | `pyproject.toml` (deps, ruff/mypy/pytest config), `Makefile` (all dev targets), `tox.ini` (py310/py311/py312), `uv.lock`, `README.md`, `CONTRIBUTING.md`, `CHANGELOG.md`, `LICENSE.md` (MIT), `CODE_OF_CONDUCT.md`. |
